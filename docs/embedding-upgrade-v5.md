# V5 嵌入升级实施合同

## 阶段与授权

当前授权范围：下载、数据处理、验证和验收材料生成。不得运行嵌入模型训练、
更新其权重或自动宣布用户验收通过。已有云模型推理属于数据处理。
数据自动检查完成后状态最多为 `ready_for_review`；收到用户对具体数据版本的
明确验收后，才可以进入模型、训练阶段。质量或样本内容变化必须重新验收。

数据操作逐步合同见 [数据准备细则](data-preparation-v5.md)。原始影像、凭据、
完整清单、大型报告与权重均在外部数据盘；Git 仅保存程序、测试、配置和脱敏摘要。

## 后续模型合同

基础编码64、精度192、空间768、时间384、最终64维。年度先验复用于四季度，
基础观测仅取查询季度，不对四季度强制一致。JL5米B1—B6、B0、10米B7—B12、
20米B13—B19分别原生编码后对齐；同名低分辨率重复波段不重复输入。

8层默认。12层相对优化后8层的少样本宏F1需增加至少1个百分点，按位置bootstrap
差值95%置信区间下界大于0，且任一主要任务退化不超过1个百分点，才进入全国阶段。
最终学生相对锁定基线提升至少2个百分点为目标，报告不确定性和资源代价。
现有架构8/12/16层分别为96,425,056 / 144,278,368 / 192,131,680参数；单位置
单季度STP主要前向约79.84 / 119.76 / 159.68 GFLOPs，新增模块另行计算。

## Git交付

每个可验证改动单独测试、commit、push至wwj并核对远端SHA。旧工作树已有未提交
修改需保留，不能捆绑无关模型改动。批次：文档；下载解压；目录；读取合同；
云质量；配准；标签统计年度索引；加载验证与验收。运行状态和完整文件清单保存在
数据盘，提交摘要须脱敏。每一步记录输入版本、参数、实际输出、处理/排除数量、
验证结果、Git提交与状态。任何未完成步骤必须明确标注，不以入口存在代替处理完成。
